# Spec 0.7a: dialects and identifier quoting

**Target release:** 0.7
**Repository:** `bijection` (the free, GPL-3.0-only crate).
**Size:** one new module, one small edit to `src/connectors/mod.rs`. Pure
functions — no database, no async, no I/O.

Read §7 before you start: this spec deliberately specifies the whole input,
including the ugly parts.

---

## 1. Why

`biject migrate` generates PostgreSQL DDL and refuses every other target. To
emit MySQL or SQL Server it has to know how each engine writes an identifier,
and those rules disagree in a way that silently corrupts a script rather than
failing loudly:

| Engine | `orders` | `my table` | `userId` |
| --- | --- | --- | --- |
| PostgreSQL | `"orders"` | `"my table"` | `"userId"` |
| MySQL | `` `orders` `` | `` `my table` `` | `` `userId` `` |
| SQL Server | `[orders]` | `[my table]` | `[userId]` |
| SQLite | `"orders"` | `"my table"` | `"userId"` |

Quoting is not optional. PostgreSQL folds an unquoted identifier to lower case,
so an unquoted `userId` becomes `userid` and stops matching a column that was
created quoted. Using the wrong quote character is worse: MySQL reads `"orders"`
as a *string literal* in its default mode, so a statement can parse and do
something other than what was meant.

This spec adds the dialect knowledge to the free crate. Statement generation
stays in the paid crate and is not your concern.

---

## 2. What to build

A new module `src/sqldialect.rs`.

```rust
/// A database engine, for the purposes of writing SQL text.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub enum Dialect {
    Postgres,
    MySql,
    SqlServer,
    Sqlite,
}
```

Derive `serde::Serialize` too, with `#[serde(rename_all = "snake_case")]`, so it
can appear in exported reports later.

### 2.1 `Dialect::name`

```rust
/// The engine's name as a person writes it, for messages.
pub fn name(&self) -> &'static str
```

Returns `"PostgreSQL"`, `"MySQL"`, `"SQL Server"`, `"SQLite"`. Match those
spellings exactly — they already appear in error messages elsewhere in the
project.

### 2.2 `Dialect::quote_ident`

```rust
/// Quote a single identifier — a column, a table, an index.
pub fn quote_ident(&self, name: &str) -> String
```

Rules, and all of them matter:

- **Always quote.** Never decide an identifier is "simple enough" to leave bare.
  An unquoted identifier is folded to lower case by PostgreSQL and to the
  server's collation rules elsewhere, and a name that happens to be a reserved
  word turns into a syntax error.
- PostgreSQL and SQLite wrap in `"`, and **an embedded `"` is doubled**:
  `a"b` becomes `"a""b"`.
- MySQL wraps in a backtick, and **an embedded backtick is doubled**:
  ``a`b`` becomes `` `a``b` ``.
- SQL Server wraps in `[` and `]`, and **an embedded `]` is doubled**:
  `a]b` becomes `[a]]b]`. An embedded `[` needs nothing.

The doubling is the whole point of this function. Without it, a name containing
the quote character ends the quoted region early and the rest of the name is
parsed as SQL. Treat that as the security-relevant case it is.

### 2.3 `Dialect::quote_table`

```rust
/// Quote a table reference, which may be schema-qualified.
pub fn quote_table(&self, name: &str) -> String
```

`reporting.prod` is two identifiers, not one. Passing it through `quote_ident`
produces a single table whose *name contains a dot*, which is not the table
anybody meant and does not exist.

Rules:

- Split on `.` **only when there is exactly one dot and neither side is empty.**
  Quote each half and join with `.`:
  `reporting.prod` → `"reporting"."prod"` on PostgreSQL,
  `` `reporting`.`prod` `` on MySQL, `[reporting].[prod]` on SQL Server.
- Anything else is quoted whole, as one identifier. That covers `prod`
  (no dot), `a.b.c` (two dots), `.prod` and `reporting.` (empty side). Guessing
  where the boundary falls in `a.b.c` would silently address a different table,
  so this does not guess.

### 2.4 `Dialect::of`

```rust
/// The dialect a source speaks, or `None` for one that is not a database.
pub fn of(config: &crate::connectors::SourceConfig) -> Option<Dialect>
```

`SourceConfig::File` returns `None` — a CSV has no dialect. Every other variant
maps to its engine. Match on the enum exhaustively; do not add a `_` arm, so
that a new variant fails the build here rather than quietly returning `None`.

## 4. Non-goals — do not do these

- **No type rendering.** Turning a `CanonicalType` into per-dialect type text is
  spec 0.7b. Do not add it here, even though it is obviously next.
- **No statement generation.** No `CREATE TABLE`, no `ALTER`, nothing that emits
  SQL beyond a quoted identifier.
- **No changes to `src/connectors/*`** beyond the one read described in §3, and
  **no changes to how queries are built or run.**
- **No new dependencies.** `serde` is already a dependency; everything else is
  `std`.
- **Do not edit** `CHANGELOG.md`, any version number, `README.md`, or anything
  under `.github/`.
- **Do not touch `biject-pro`.** It is a different repository and not yours for
  this task.

## 5. Tests

All in a `#[cfg(test)] mod tests` inside `src/sqldialect.rs`.

Test names are sentences about behaviour. Match the style already in
`src/sqltype.rs`.

| Test name | Must assert |
| --- | --- |
| `every_dialect_quotes_the_way_its_server_expects` | `quote_ident("orders")` is `"orders"` for Postgres and Sqlite, `` `orders` `` for MySql, `[orders]` for SqlServer |
| `an_identifier_is_always_quoted_even_when_it_looks_safe` | `quote_ident("id")` is quoted for all four. Comment: PostgreSQL folds an unquoted identifier to lower case, so a quoted `userId` stops matching |
| `case_survives_because_the_identifier_is_quoted` | `Postgres.quote_ident("userId")` is `"userId"`, not lowercased |
| `an_embedded_quote_character_is_doubled_not_dropped` | `Postgres.quote_ident("a\"b")` is `"a""b"`; `MySql.quote_ident("a`b")` is `` `a``b` ``; `SqlServer.quote_ident("a]b")` is `[a]]b]`. Comment: without doubling, the name ends the quoted region early and the rest is parsed as SQL |
| `a_bracket_dialect_only_doubles_the_closing_bracket` | `SqlServer.quote_ident("a[b")` is `[a[b]` |
| `a_schema_qualified_table_is_two_identifiers` | `quote_table("reporting.prod")` gives `"reporting"."prod"`, `` `reporting`.`prod` ``, `[reporting].[prod]` for the three respectively |
| `an_unqualified_table_is_left_as_one` | `quote_table("prod")` equals `quote_ident("prod")` for all four |
| `an_ambiguous_table_reference_is_not_split_apart` | `quote_table("a.b.c")`, `quote_table(".prod")` and `quote_table("reporting.")` each quote the whole string as one identifier. Comment: guessing where the boundary falls would address a different table |
| `a_file_has_no_dialect` | `Dialect::of` on a `SourceConfig::File` is `None` |
| `each_database_source_reports_its_own_dialect` | `Dialect::of` returns the right variant for a Postgres, MySQL, SQL Server and SQLite `SourceConfig`. Build them with `crate::connectors::parse_source_uri` rather than by hand, so the test breaks if URI parsing changes |
| `each_dialect_has_a_name_a_person_would_recognise` | `name()` returns exactly `PostgreSQL`, `MySQL`, `SQL Server`, `SQLite` |

Example URIs for the `Dialect::of` test:

```
postgres://u:p@h:5432/db
mysql://u:p@h:3306/db
sqlserver://u:p@h:1433/db
sqlite://some.db
data.csv
```

`parse_source_uri` takes a second argument for the table or query; pass
`Some("t")`.

## 7. A note on how this spec is written

The previous spec in this series had one defect, and it was the spec's fault
rather than the implementer's: it described what to do with the text before and
inside a type's parentheses, and never said what to do with the text *after*
them. The implementation followed it exactly and silently dropped
`decimal(12,2) unsigned` down to `decimal(12,2)`.

So §2.2 and §2.3 above enumerate the awkward inputs on purpose — embedded quote
characters, two dots, an empty side. Those are not edge cases to be tidied up
later; they are the specification. If you find an input this spec does not
cover, that is a hole worth reporting rather than filling with a guess.
