# Spec: the desktop app states what it does not do

**Target release:** 1.0
**Repository:** `bijection` (free crate) — `tauri-app/` and `README.md`
**Depends on:** 1.0a. That one makes the app's *schema report* complete; this
one is about the app's *feature set*, and the two should not be reviewed
together.
**Size:** one panel, one README paragraph. The smallest spec in the 1.0 queue.

---

## 1. The gap

The CLI has three things the desktop app does not:

| CLI | In the app? |
| --- | --- |
| `biject batch --manifest …` | no |
| `biject schema --policy contract.json` | no |
| `--output` / `--format` export to a file | no |

The roadmap's line on this is "desktop app parity, or an honest scope cut", and
the cut is the answer. Batch runs and schema contracts are CI-shaped features
and nobody runs CI in a window; building them into a GUI would be work spent
where it is least used.

**But a cut only counts if it is stated.** Somebody who has only ever opened the
app has no way to know the tool can do these things, and this project's whole
posture is that a partial answer must say it is partial. That applies to what
the software offers as much as to what a comparison found.

---

## 2. What to build

### 2.1 A panel in the app

Somewhere permanently visible without scrolling past a result — beside the
command tabs, or as a short block under them. Not a modal, not a dismissible
toast: a person who dismisses it once still needs the information next month.

Content, in your own wording:

> This app covers schema and data comparison. Three things are command-line
> only: running many comparisons from a manifest (`biject batch`), checking a
> comparison against a policy file (`--policy`), and writing results to a file
> (`--output`). The command line is installed alongside this app.

Link to the README section from 2.2 if linking out is easy; do not build an
in-app help browser to make that work.

**Do not phrase it as a limitation of the app relative to some ideal.** It is a
statement of where each part of the tool lives. The CLI likewise has no saved
connection profiles, which is the app's alone — say that too, in the same
breath. It is true, it is useful, and it stops the panel reading as an apology.

### 2.2 A README section

`README.md` documents the desktop app. Add a short subsection listing the same
three CLI-only features and the one app-only feature, and say plainly that the
app is a deliberate subset rather than an unfinished port. Two short paragraphs.
Do not reproduce this spec.

This is one of the few specs permitted to edit `README.md`.

---

## 3. Non-goals

- **Do not build batch, policy or export into the app.** That decision has been
  taken. If you think one of them is easy enough to change the decision, say so
  in your report and leave the code alone — the point of stating a cut is that
  it is stated, not that it is permanent.
- **No Rust changes.** No new Tauri command, no new library function.
- **Do not add a settings page, a help menu, or an about dialog** to house this.
  One panel.
- **No new dependencies.**

---

## 4. Tests

None to write. Verify by running the app and reading it.

| What to check | Expected |
| --- | --- |
| Open the app, do nothing else | The panel is visible without scrolling |
| Run a schema comparison | The panel is still visible, and has not moved the result off screen |
| Resize the window small | The panel wraps rather than overlapping the controls |
| The README section | Names the same three features as the panel, and no others |

That last row is the one that rots. Two lists of the same three things will
disagree within a year unless somebody checks; read them side by side now.
